**Scope**: End-to-End Treasury Protection, Confidential Policy Enclave, On-Chain Verification, and DEX Execution Engine.

## 1. System Components & Architecture Overview

The XRPShield system consists of 16 interconnected components operating across Web Browser, Backend API, Confidential Compute Enclave, Smart Contracts, and Decentralized Exchanges:

1. **Web Frontend**: Single-page application rendering vault telemetry, risk policy creator, and DEX quote preview.
2. **MetaMask Wallet**: Web3 provider handling user key management, transaction signing, and message signatures.
3. **Spring Boot Backend**: REST service handling metadata indexing, DEX quote calculation, and notification dispatch.
4. **Supabase Storage**: Off-chain relational database storing user profiles, notification settings, and public telemetry.
5. **OpenAI LLM**: Natural language interface providing advisory parameter assistance to users.
6. **XRPShieldVault.sol**: Production smart contract custodying FXRP/USDT0 assets and enforcing execution state machines.
7. **Policy Commitment**: Canonical ECIES-encrypted cryptographic digest of private financial risk policies.
8. **Flare FTSOv2**: Decentralized oracle protocol delivering low-latency, tamper-proof XRP/USD price feeds on-chain.
9. **Flare FCC Infrastructure**: Flare Confidential Compute extension framework managing TEE machine registration and instruction dispatch.
10. **TEE Enclave (Extension `0x585250...001`)**: Secure hardware enclave evaluating private risk policies in isolated memory.
11. **ActionResult Struct**: Cryptographically bound EIP-712 attestation payload generated by TEE enclave memory.
12. **HedgeExecutor.sol**: Dedicated execution contract managing DEX router approvals and token swap execution.
13. **SparkDEX / BlazeSwap Router**: Uniswap V2 compatible DEX router (`0x600109D9cDe3267E1408892f39C27DBdf8dd6B4B`) executing spot swaps.
14. **FXRP ERC-20 Token**: Asset token wrapped on Flare Coston2 representing underlying XRP reserve assets.
15. **USDT0 ERC-20 Token**: Stablecoin ERC-20 asset on Coston2 representing hedged cash reserves.
16. **Coston2 RPC Endpoint**: JSON-RPC interface (`https://coston2-api.flare.network/ext/C/rpc`) connecting participants to EVM state.

## 2. Trust Model & System Boundaries

```text
 ┌────────────────────────────────────────────────────────────────────────┐
 │                      SYSTEM TRUST BOUNDARY MATRIX                      │
 ├───────────────────┬────────────────────────────────────────────────────┤
 │ Component         │ Trust Scope / Non-Trust Mandate                   │
 ├───────────────────┼────────────────────────────────────────────────────┤
 │ Web Frontend      │ ❌ UNTRUSTED for financial authorization          │
 │ Spring Boot       │ ❌ UNTRUSTED for financial authorization          │
 │ Supabase DB       │ ❌ UNTRUSTED as blockchain state                   │
 │ OpenAI LLM        │ ❌ UNTRUSTED for financial execution              │
 │ Smart Contracts   │ ✅ AUTHORITATIVE on-chain state & risk limits      │
 │ Flare FCC / TEE   │ ✅ AUTHORITATIVE confidential policy evaluation   │
 └───────────────────┴────────────────────────────────────────────────────┘
```

### Explicit Trust Mandates:
- **Web Frontend**: trusted ONLY for user interface display. Frontend MUST NOT be trusted for financial authorization, price validation, or decision generation.
- **Spring Boot Backend**: trusted ONLY for advisory data indexing and REST caching. Backend MUST NOT be trusted for financial authorization or TEE attestation generation.
- **Supabase Storage**: trusted ONLY for off-chain metadata storage. Supabase MUST NOT be trusted as a source of truth for balances, policy statuses, or execution confirmations.
- **OpenAI LLM**: trusted ONLY for advisory text formatting and non-financial guidance. OpenAI MUST NOT be trusted for hedge decisions or execution parameters.
- **Smart Contracts (`XRPShieldVault.sol` & `HedgeExecutor.sol`)**: AUTHORITATIVE on-chain root of trust for asset custody, EIP-712 verification, anti-replay tracking, and slippage enforcement.
- **Flare FCC Enclave**: AUTHORITATIVE enclave root of trust for confidential policy decryption and quantitative hedge calculation.

## 4. Residual Risk Assessment & Conclusions
While on-chain smart contract authority and cryptographic TEE attestations eliminate financial authorization bypass, residual risks remain in:
1. **Underlying TEE Hardware Vulnerabilities**: Hardware-level enclave exploits (e.g., side-channel attacks on SGX/TDX memory).
2. **MetaMask Wallet Compromise**: Private key compromise of the vault owner wallet allowing withdrawal by unauthorized parties.
3. **Decentralized DEX Volatility**: Extreme market illiquidity resulting in legitimate swap reverts due to `minimumAmountOut` protection.

> [!NOTE]
> All critical financial execution pathways are 100% bound to verified on-chain conditions. Frontend, backend, OpenAI, and Supabase components hold zero financial authority.
