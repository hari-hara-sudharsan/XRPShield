Comprehensive developer & judge guide to the confidential treasury protection pipeline on Flare Coston2 Testnet

1. System Architecture & Topology

XRPShield is a non-custodial treasury risk management protocol built on Flare Network. It combines Flare Confidential Compute (FCC) TEE hardware enclaves with FTSOv2 decentralized price feeds and SparkDEX V2 liquidity pools to deliver automated FXRP hedging without exposing user risk parameters on-chain.

🌐 Flare Coston2 EVM

Chain ID 114. Settles XRPShieldVault.sol custody and HedgeExecutor.sol swaps.

🔒 Flare FCC TEE Enclave

Extension 0x585250...001. Evaluates confidential ECIES policies inside isolated hardware memory.

📈 FTSOv2 Oracle

Feed 0x01...001. Delivers real-time, tamper-proof XRP/USD price feeds on-chain.

3. Security Invariants & Emergency Controls

  • FCC Zero Bypass: Direct calls to executeHedge() revert unless preceded by a verified EIP-712 TEE attestation.
  • Strict Recipient Custody: Swapped USDT0 funds must return directly to address(XRPShieldVault); external wallet recipients revert.
  • Zero Capital Lock Emergency Pause: Calling setPaused(true) halts new hedge executions while leaving withdrawFXRP() 100% active for user fund retrieval.
  • Circuit Breaker Manager: Automatically pauses execution after 3 consecutive external failure events.
