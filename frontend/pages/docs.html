01

System Architecture & Topology

Core execution boundaries and Flare-native infrastructure dependencies.

XRPShield is a non-custodial treasury risk-management protocol designed to keep sensitive treasury policies confidential while using Flare-native infrastructure for market data, computation and settlement. The system connects Flare Confidential Compute (FCC), FTSOv2, and a DEX execution layer around the XRPShield vault and hedge contracts.
◈
Flare Coston2 EVM
Chain ID 114. Hosts XRPShield vault state, authorization checks and settlement transactions.
◉
Flare Confidential Compute
FCC extension evaluates confidential policy inputs and produces an authorized decision result without exposing the underlying strategy on-chain.
◌
Flare Data + Execution
FTSOv2 provides decentralized market data, while the configured DEX execution layer handles the authorized hedge settlement.

03

Security Invariants & Emergency Controls

Contract-level constraints that protect the execution boundary and user funds.

⛨
FCC Zero-Bypass Execution Gate
Direct hedge execution is rejected unless the required verified authorization path has been satisfied.
⇢
Strict Recipient Custody
Hedge settlement is constrained so the resulting asset remains under the XRPShield vault custody boundary.
◫
Emergency Execution Pause
The pause mechanism blocks new hedge execution while preserving the user's ability to retrieve supported vault funds.
⚡
Failure Circuit Breaker
Consecutive external execution failures can trigger the configured protection mechanism, reducing the chance of repeated failed settlement attempts.
