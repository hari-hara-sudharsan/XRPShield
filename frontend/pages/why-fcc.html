CONFIDENTIAL COMPUTE ARCHITECTURE COMPARISON

Why Flare Confidential Compute?

Public EVM execution is transparent by design. XRPShield separates sensitive treasury policy evaluation from public settlement so that private strategy parameters do not need to become public contract state.

◇

WITHOUT CONFIDENTIAL COMPUTE

PUBLIC EVM / CENTRALIZED SERVER

A standard public smart contract can enforce rules, but the parameters supplied to public transaction execution are not inherently private.

  • ✕ Trigger thresholds can reveal when a treasury intends to react.
  • ✕ Hedge allocation ratios can expose the intended defensive position.
  • ✕ Notional and execution limits can disclose treasury risk boundaries.
  • ✕ A centralized policy server introduces an operator trust boundary.
PRIVATE POLICY → SERVER / CALldata → PUBLIC EXECUTION
◈

WITH XRPShield CONFIDENTIAL COMPUTE

PRIVATE EVALUATION · PUBLIC SETTLEMENT

XRPShield moves sensitive policy evaluation into the confidential-compute boundary while leaving the final settlement path independently verifiable on-chain.

  • ✓ Policy material can be protected before submission rather than exposed as ordinary plaintext inputs.
  • ✓ Sensitive policy evaluation occurs inside the FCC execution boundary.
  • ✓ The risk engine can evaluate treasury conditions against the relevant market/oracle data.
  • ✓ A signed ActionResult provides an authorization boundary for downstream execution.
ENCRYPTED POLICY → FCC EVALUATION → ACTION RESULT → ON-CHAIN SETTLEMENT
XRPShield DESIGN PRINCIPLE
Keep the strategy private. Keep the settlement verifiable. Confidential compute handles the sensitive policy-evaluation boundary, while the public chain remains the source of truth for the resulting transaction and settlement state.
